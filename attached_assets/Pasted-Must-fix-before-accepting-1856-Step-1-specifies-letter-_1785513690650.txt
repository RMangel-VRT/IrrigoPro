Must fix before accepting #1856

Step 1 specifies letter: text("letter").notNull().default("") and creates the unique index in the same migration.

In Postgres, NULLs in a unique index are treated as distinct, but empty strings are not. Every existing controller gets "", so the moment you create a unique index on (companyId, customerId, branchName, letter), your six-controller customer has six rows all holding "" — and index creation fails outright. Even if it somehow got created, every insert before the backfill would collide on "".

The ordering is also inverted: the index is created in step 1, the backfill is step 6.

Correct sequence:

Add letter as nullable — text("letter"), no notNull, no default.
Run the backfill so every row has a real letter.
Then create the unique index.
Optionally add notNull afterwards, once nothing is null.

My spec had it nullable for exactly this reason. Worth telling Replit explicitly, because "notNull default empty string plus unique index" is a plausible-looking change that silently breaks.

#1857 has a milder version of the same thing — step 1 says "replace the unique index, register and run the migration," step 2 says don't create the index until the backfill reports zero ambiguous rows. Make it explicit: add column, backfill, then swap the index.
