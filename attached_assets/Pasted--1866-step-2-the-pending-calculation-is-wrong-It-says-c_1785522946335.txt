#1866 step 2 — the pending calculation is wrong

It says compute pending "from open work orders (status work_completed or in_progress) not yet linked to an invoice, following the same pattern as unbilledExposure." Three problems, stacking:

unbilledExposure doesn't sum work orders. It sums work orders + billing sheets + wet-check billings (financial-pulse.ts:1344–1360).
It has no date window at all. It's a running total of everything ever unbilled. Copy it into a monthly bar and July shows March's unbilled work.
Budget spend uses neither. It counts only uninvoiced wet-check billings, filtered by workDate inside the month (financial-pulse.ts:1409) — that's what Task #814 established.

So as written, #1866 computes a different, larger, un-windowed pending number than #1864's shared function. That's a fourth disagreeing figure, which is precisely the bug this sequence exists to eliminate.

The fix is simple: step 2 calls the shared function from #1864 for both invoiced and pending. #1864 already returns { invoiced, pendingNotBilled, total } as a split for exactly this reason. Step 2 currently says "reuses the shared spend function for invoiced amounts" — drop that qualifier and delete the unbilledExposure reference entirely.
