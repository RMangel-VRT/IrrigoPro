## Multi-tenancy (Rule 1)

`customer_budget_months` carries `companyId` NOT NULL, unique on `(companyId, customerId, year, month)`, indexed by `companyId`. Generation, regeneration, reads and the roll-up all resolve scope from the customer's own company, never from caller input. The backfill runs per company. A cross-company read returns 404, not 403.

## Done looks like

- A customer's 2026 annual goal is entered once in the customer profile and produces the seven monthly figures the spreadsheet produces: $7,500 → 0 / 750 / 1,500 / 1,500 / 1,500 / 1,500 / 750.
- A single month can be overridden without changing the annual goal, and the drift notice appears.
- `GET /api/customers/:id/budget-usage` reports against the current month's allocation with season-to-date alongside.
- A customer with no goal reads as **unset** everywhere — never zero, never over.
- Budget alerts fire against monthly allocations using the same spend figure the API reports.
- Nothing unrelated to budgets was reverted by this change.
