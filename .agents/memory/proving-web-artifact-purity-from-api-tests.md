---
name: Proving a web-artifact function from an api-server test
description: How to assert on output generated by irrigopro code from a node:test in api-server without breaking tsc rootDir.
---

When a guarantee spans surfaces owned by different packages — "this data never
reaches the PDF, an email, or the CSV" — put all three assertions in one test
group in the api-server package, and reach into the web artifact for the third.

Two obstacles, both solved the same way:

1. **The web module usually cannot be imported at all.** Anything importing a
   Vite alias (`@/lib/...`), the DOM, or the query client explodes under plain
   Node. Split the pure part into a sibling module with zero imports and have
   the original re-export it, so every existing call site is untouched.
2. **A static cross-package import breaks the typecheck.** It pulls a file
   outside the package's `rootDir` into its program. Use a *computed*
   specifier — `await import(new URL("../../../irrigopro/src/lib/x.ts",
   import.meta.url).href)` — which TypeScript does not resolve statically.
   There is precedent in the repo for reaching across artifacts this way.

**Why:** a "notes never leak" proof that lives in three separate suites, one
per package, is three things someone can delete independently. One group that
renders all three real artifacts and greps the bytes fails loudly the first
time someone adds a field to a template.

**How to apply:** whenever a cross-cutting invariant has to be asserted on
*generated output* rather than on intent. If the generator builds its body
inline inside a method that also does IO (fetching from object storage,
sending mail), extract the body builder into a pure exported function first —
copy unchanged — so the test can generate without the IO.
